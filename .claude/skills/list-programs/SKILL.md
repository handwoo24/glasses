# 기관 사업 목록화

지방재정365 세부사업 전체에 예산서의 부서·정책사업·단위사업을 붙이고, 사업 후보로 묶은 뒤, 평가 대상을 골라 사업 카드(`programs/{기관코드}.{사업}`)로 올린다. 결과는 사이트 `/orgs/{기관코드}/programs`에서 바로 보인다.

첫 기준선: 고양특례시 2026 (2026-10-28). 세부사업 3,203건 → 행정경비·재무 287건 제외 → 사업 후보 2,267개 → 평가 대상 76개.

## 순서

1. **기관 확인.** `npm run pipeline -- get orgs/{기관코드}`. 없으면 공식 출처(행정표준코드, 지방재정365 자치단체 코드 `lafCd`)로 확인한 뒤에만 넣는다.
2. **세부사업 전체.** 지방재정365 세부사업별 세출현황(`retvLstExcDtlsBybsnAneSitu.do`, POST, `pageSize` 5000, `inqSgg`=lafCd, `inqYmd`=조회일)을 받아 `materials/m-…`로 남긴다. 고양시 예: 자료 `m-03b9911b25cc`의 `params`. 세부사업마다 `budgetLines/{코드}-{연도}`를 쓴다.
3. **예산서.** 그 해 본예산서와 지금까지의 추경예산서를 모두 받아 자료로 남긴다(기관 누리집 예산 게시판). 추경 사업명세서는 **바뀐 세부사업만** 담으므로 본예산서가 꼭 있어야 한다.
4. **텍스트 추출.** `npm run catalog -- pdf-text <예산서.pdf> <출력.txt>` (1,300쪽에 20초 안팎).
5. **사업 후보.** `npm run catalog -- candidates --lines <지방재정365.json> --book <본예산.txt> --book <추경.txt> … --out <후보.json>`. 출력의 "부서를 찾지 못한 후보"가 10%를 크게 넘으면 빠진 추경(특히 2회 추경)이 없는지 먼저 본다.
6. **평가 대상 고르기** (아래 기준). 사람의 판단이 들어가는 단계이므로 후보 목록과 고른 이유를 사용자에게 보여 주고 정한다.
7. **카드 올리기.** 카드마다 JSON을 만들어 `npm run pipeline -- put programs/{기관코드}.{slug} card.json`. 이미 있는 카드는 덮어쓰지 말고 `budgetLines`·`departments`만 보탠다.
8. **확인.** `npm run pipeline -- ls programs`로 개수, 사이트 `/orgs/{기관코드}/programs`에서 단계 줄.

## 평가 대상 기준 (2026-10-28 사용자와 정함)

- 예산현액 **10억 원 이상**, 그리고 **국비+도비가 절반 미만**인 시 사업.
- 국비·도비가 절반 넘는 **국가 제도**(기초연금, 보육료, 생계급여, 장기요양 등)는 빼고 나중에 중앙 사업으로 평가해 연결한다.
- **국비 공모로 시가 짓는 시설**(건립·조성·정비 공사)은 국비 비중과 상관없이 넣는다.
- **일상 운영비**(공원·도로·청사 유지관리, 통반장 활동, 위탁 청소·수집운반, 의원 유급제, 지방세 고지 등)는 뺀다.
- 넣는 것: 건설·조성, 시가 만든 시책(출산지원금, 누리버스 등), 출자·출연기관 지원(도시관리공사, 문화재단, 산업진흥원, 연구원 …).
- 1억 이상 전부는 하지 않는다: 1,133개 × 리포트 2~4시간으로 1년이 넘는다.

## 카드 만들기

- `slug`: 영문 소문자 kebab, 짧고 사업을 알아볼 수 있게(`bus-depot-wondang`, `kintex-hall3`). 연도를 넣지 않는다.
- `name`: 세부사업 이름 그대로. 리포트 세션이 고칠 수 있다.
- `budgetLines`: 후보의 `codes` 전부. 같은 사업이 여러 세부사업이면 한 카드로 합친다(원흥복합문화센터 건립 + 원흥 도서관 건립 지원).
- `departments`: 후보의 `departments`. 비어 있으면 빈 배열(화면에 "부서 확인 전").
- `field`: 지방재정365 분야·부문(`sector`·`subsector`).
- `status`: 예산이 잡혀 있으면 `진행 중`. 리포트 세션이 바로잡는다.
- `priority.score`: 100억 이상이거나 10억 이상에 집행률 30% 미만이면 `high`, 30억 이상 `medium`, 나머지 `low`. `why`에는 숫자만: "2026 예산현액 113억 원, 2026-10-26까지 집행률 4% (지방재정365)". 집행률은 판정이 아니다.

## 걸려 넘어진 것

- 지방재정365 세출현황 JSON에는 부서·정책사업·단위사업이 **없다**. 예산서로만 붙일 수 있다.
- 같은 이름의 세부사업이 구청·보건소·동마다 따로 있다(주민자치센터운영 44건). 이름으로 합친다.
- 예산서 PDF 텍스트는 글자 사이가 띄어져 있다(`체 육 정 책 과`). 비교는 공백을 지우고 한다.
- 단위사업과 세부사업 이름이 같을 수 있다(환경에너지시설운영). 이름 다음 줄이 편성목(201 …)이면 세부사업이다.
- 산출 내역 금액 줄(`시)9,540,800,000원`)이 단위사업 자리에 끼어들 수 있다. candidates가 걸러 낸다.
- 부서를 못 찾는 것은 대부분 지난해 이월사업, 빠진 추경의 신규 사업, 기금이다. 기금은 별도 기금운용계획서에 있다.
- 상수도·하수도 공기업특별회계는 지방재정365 세출현황에 없다. 출자·출연기관이 직접 하는 사업도 시 예산에는 출연금 한 줄로만 보인다.
- 운영 Firestore에 쓸 때는 `GLASSES_FIRESTORE_PROJECT`와 `GOOGLE_CLOUD_QUOTA_PROJECT`를 운영 프로젝트로 정한다. 운영 정보는 저장소·커밋에 쓰지 않는다.
