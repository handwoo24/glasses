# 기관 사업 목록화

지방재정365 세부사업 전체에 예산서의 부서·정책사업·단위사업을 붙이고, 사업 후보로 묶은 뒤, 평가 대상을 골라 사업 카드(`programs/{기관코드}.{사업}`)로 올린다. 결과는 사이트 `/orgs/{기관코드}/programs`에서 바로 보인다.

첫 기준선: 고양특례시 2026 (2026-10-28). 세부사업 3,203건 → 행정경비·재무 287건 제외 → 사업 후보 2,267개 → 평가 대상 76개.
광역·중앙 (2026-10-29): 서울특별시 세부사업 4,479건 → 평가 대상 212개, 경기도 6,001건 → 86개, 중앙 62개 소관 9,436건 → 336개. 절차는 아래 "광역자치단체"와 "중앙"을 따른다.

## 순서

1. **기관 확인.** `npm run pipeline -- get orgs/{기관코드}`. 없으면 공식 출처(행정표준코드, 지방재정365 자치단체 코드 `lafCd`)로 확인한 뒤에만 넣는다.
2. **세부사업 전체.** 지방재정365 세부사업별 세출현황(`retvLstExcDtlsBybsnAneSitu.do`, POST, `pageSize` 5000, `inqSgg`=lafCd, `inqYmd`=조회일)을 받아 `materials/m-…`로 남긴다. 고양시 예: 자료 `m-03b9911b25cc`의 `params`. 세부사업마다 `budgetLines/{코드}-{연도}`를 쓴다.
3. **예산서.** 그 해 본예산서와 지금까지의 추경예산서를 모두 받아 자료로 남긴다(기관 누리집 예산 게시판). 추경 사업명세서는 **바뀐 세부사업만** 담으므로 본예산서가 꼭 있어야 한다.
4. **텍스트 추출.** `npm run catalog -- pdf-text <예산서.pdf> <출력.txt>` (1,300쪽에 20초 안팎).
5. **사업 후보.** `npm run catalog -- candidates --lines <지방재정365.json> --book <본예산.txt> --book <추경.txt> … --out <후보.json>`. 출력의 "부서를 찾지 못한 후보"가 10%를 크게 넘으면 빠진 추경(특히 2회 추경)이 없는지 먼저 본다.
6. **평가 대상 고르기** (아래 기준). 사람의 판단이 들어가는 단계이므로 후보 목록과 고른 이유를 사용자에게 보여 주고 정한다.
7. **카드 올리기.** 카드마다 JSON을 만들어 `npm run pipeline -- put programs/{기관코드}.{slug} card.json`. 수백 건이면 `{"path","value"}` 한 줄씩 JSONL로 모아 `npm run pipeline -- put-many 파일.jsonl` (카드 → 카탈로그 순서: 카탈로그 줄의 `program`이 카드를 가리킨다). 이미 있는 카드는 덮어쓰지 말고 `budgetLines`·`departments`만 보탠다.
8. **확인.** `npm run pipeline -- ls programs`로 개수, 사이트 `/orgs/{기관코드}/programs`에서 단계 줄.

## 평가 대상 기준 (2026-10-28 사용자와 정함)

- 예산현액 **10억 원 이상**, 그리고 **국비+도비가 절반 미만**인 시 사업.
- 국비·도비가 절반 넘는 **국가 제도**(기초연금, 보육료, 생계급여, 장기요양 등)는 빼고 나중에 중앙 사업으로 평가해 연결한다.
- **국비 공모로 시가 짓는 시설**(건립·조성·정비 공사)은 국비 비중과 상관없이 넣는다.
- **일상 운영비**(공원·도로·청사 유지관리, 통반장 활동, 위탁 청소·수집운반, 의원 유급제, 지방세 고지 등)는 뺀다.
- 넣는 것: 건설·조성, 시가 만든 시책(출산지원금, 누리버스 등), 출자·출연기관 지원(도시관리공사, 문화재단, 산업진흥원, 연구원 …).
- 1억 이상 전부는 하지 않는다: 1,133개 × 리포트 2~4시간으로 1년이 넘는다.

## 광역자치단체 (서울·경기 2026-10-29)

- 기관코드: 서울특별시 6110000(lafCd 1100000), 경기도 6410000(lafCd 4100000). 지방재정365 목록 요청은 기초와 같고 `inSgg`·`inqCap`만 바꾼다(`subCode`·`inqCap` 11/41, `inqSggT` "서울본청"/"경기본청").
- **예산서 PDF 없이** 부서를 붙인다. 세부사업 상세(`retvDtlsBybsnAneSituDts.do`, form POST `dbizCd·lafCd·fyr·inqYmd·menuId=LF3120204·uprMenuId=LF3120202·menuParaCn=STST`)의 `var list3`에 `deptNm`(본부_과), `pbizCn`(정책사업), `ubizNm`(단위사업), `tbc`(총사업비), 사업목적·기간·위치가 있다. 10억 이상만 받아도 서울 1,512건이 초당 1건 안팎으로 25분쯤 걸린다. 상세 전체를 JSONL 한 파일로 모아 자료 하나로 남긴다(서울 `m-a660d1923bf4`, 경기 `m-9ae6fdcf11af`).
- 경기도 세부사업 이름에는 `(자체/직접)`·`(자체/지원)`·`(국비/직접)`이 붙는다. 직접은 도가 하고 지원은 시군에 준다. 이름 비교·카드 이름에서는 떼고, 후보에 `mode`로 남긴다.
- 평가 대상 기준(사용자, 2026-10-29): **예산현액 100억 원 이상 + 국비 절반 미만**. 전출금·교부금·기금 예탁·채무 상환·반환금, 보육료·급여·장기요양 같은 법정 지출, 도로·공원 유지관리와 위탁·청사 관리, 융자는 뺀다. 출연기관 지원, 시군 지원, 시책 현금 지원(청년수당·기본소득), 광역철도 분담금은 넣는다.
- 우선순위: 1,000억 이상이거나 집행률 30% 미만 high, 300억 이상 medium, 나머지 low.

## 중앙 (2026-10-29)

- 열린재정 OpenAPI 키는 필요 없다. 누리집이 부르는 내부 JSON을 쓴다(공공누리 제3유형).
  - 세부사업 예산편성현황(총액·총계, 천원): `POST https://www.openfiscaldata.go.kr/op/fa/sm/service/preview/rowSheet/gridDataLoad.do` 본문 `{"odtId":"D46IFSSM0WKG88ISZ73URDUBR","dsId":"VW_OPFI938","rlsSvTyCd":"S","odtSvSeq":"1","pageIndex":"1","pageSize":"20000","traDataFextNm":"DATA","selectWon":"1","decimalPointLevel":"0","FSCL_YY":"2026"}`. 이름만 있고 코드가 없다. 2026 자료 `m-0a5f9c1294e7`.
  - 월별 집행실적(백만원, 코드 포함): `POST …/op/ko/be/selectMnlExeOutList.do` 본문 `{"paramVO":{"pageIndex":"1","pageSize":"20000","acntYr":"2026","exeMm":"09"}}`. 2026년 9월분 자료 `m-c631cb067008`.
- 카탈로그 코드는 `cg-{소관}-{회계}-{계정}-{프로그램}-{단위}-{세부}`(집행실적 코드). 총액표와 이름 5개(소관·회계·프로그램·단위·세부사업)로 맞추면 9,436건 중 8,560건이 붙는다. 못 붙는 것은 `cg-n{이름 해시 10자리}`, 이름이 겹치는 26건은 카탈로그에서 뺐다.
- 소관 → 행정표준 기관코드는 행정표준코드관리시스템(`www.code.go.kr`)에서 확인한다(`orgCodeFrameL.do` POST, `fullNm`과 `lowNm`을 함께, 먼저 첫 화면을 열어 `clientid` 쿠키). 2025-10·2026-01 개편 기관은 모두 새 코드다(재정경제부 1053000, 기후에너지환경부 1482000, 산업통상부 1451000, 성평등가족부 1384000 …). 공공데이터포털 행정표준기관코드 API는 우리 키가 등록돼 있지 않다.
- 기관 종류: 국회·대법원·헌법재판소·중앙선관위·감사원은 `헌법기관`, 국가인권위·공수처·국정원·국가교육위·이태원특조위·민주평통은 `독립기관`. 두 기관이 묶인 소관(국무조정실 및 국무총리비서실)은 앞 기관 코드를 쓰고 이름은 소관 이름 그대로.
- 평가 대상 기준(사용자, 2026-10-29): **2026 확정 예산 1,000억 원 이상**의 주요사업비·일반지출 가운데 재량 사업. 교부금·교부세, 연금·보험 급여, 국채 이자·상환, 융자·출자, 예비비, 보육료·수당·장학금은 빼고, 기본경비·인건비, 군 연료·피복·급식·공공요금, 시설 유지보수, 보증·유동화, 분담금 납부도 뺀다.
- 우선순위: 1조 이상이거나 9월까지 집행률 30% 미만 high, 3,000억 이상 medium, 나머지 low. `departments`는 비워 둔다(열린재정에 부서가 없다).
- 국고보조사업은 나중에 지자체 카드의 `nationalProgram`이 이 카드를 가리켜 정부 → 지자체 → 업체 흐름을 잇는다.

## 카드 만들기

- `slug`: 영문 소문자 kebab, 짧고 사업을 알아볼 수 있게(`bus-depot-wondang`, `kintex-hall3`). 연도를 넣지 않는다.
- `name`: 세부사업 이름 그대로. 리포트 세션이 고칠 수 있다.
- `budgetLines`: 후보의 `codes` 전부. 같은 사업이 여러 세부사업이면 한 카드로 합친다(원흥복합문화센터 건립 + 원흥 도서관 건립 지원).
- `departments`: 후보의 `departments`. 비어 있으면 빈 배열(화면에 "부서 확인 전").
- `field`: 지방재정365 분야·부문(`sector`·`subsector`).
- `status`: 예산이 잡혀 있으면 `진행 중`. 리포트 세션이 바로잡는다.
- `priority.score`: 100억 이상이거나 10억 이상에 집행률 30% 미만이면 `high`, 30억 이상 `medium`, 나머지 `low`. `why`에는 숫자만: "2026 예산현액 113억 원, 2026-10-26까지 집행률 4% (지방재정365)". 집행률은 판정이 아니다.

## 걸려 넘어진 것

- 지방재정365 세출현황 JSON에는 부서·정책사업·단위사업이 **없다**. 예산서로만 붙일 수 있다.
- 같은 이름의 세부사업이 구청·보건소·동마다 따로 있다(주민자치센터운영 44건). 이름으로 합친다.
- 예산서 PDF 텍스트는 글자 사이가 띄어져 있다(`체 육 정 책 과`). 비교는 공백을 지우고 한다.
- 단위사업과 세부사업 이름이 같을 수 있다(환경에너지시설운영). 이름 다음 줄이 편성목(201 …)이면 세부사업이다.
- 산출 내역 금액 줄(`시)9,540,800,000원`)이 단위사업 자리에 끼어들 수 있다. candidates가 걸러 낸다.
- 부서를 못 찾는 것은 대부분 지난해 이월사업, 빠진 추경의 신규 사업, 기금이다. 기금은 별도 기금운용계획서에 있다.
- 상수도·하수도 공기업특별회계는 지방재정365 세출현황에 없다. 출자·출연기관이 직접 하는 사업도 시 예산에는 출연금 한 줄로만 보인다.
- `budgetLines`는 사이트가 전체를 읽지 않는다. 기관 합계는 `org`+`year` 집계 쿼리(복합 색인 `firestore.indexes.json`), 사업 금액은 카드가 가리키는 코드만 읽는다.
- 운영 Firestore에 쓸 때는 `GLASSES_FIRESTORE_PROJECT`와 `GOOGLE_CLOUD_QUOTA_PROJECT`를 운영 프로젝트로 정한다. 운영 정보는 저장소·커밋에 쓰지 않는다.
