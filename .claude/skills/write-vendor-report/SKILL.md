# 업체 리포트 작성

업체 리포트는 “이 업체가 좋은 회사인가”가 아니라 “이 사업에서 맡은 계약을 약속대로 해냈나”를 묻는다. 평가 단위는 **사업 × 업체**이고, 근거는 계약·검수·지급·제재 같은 공식 기록뿐이다. 사업 리포트 작성(`write-report`)의 원칙(한 세션 하나, 공식 자료만, 언론은 단서, 사실 원장에서 출발, 이름 가리기)을 그대로 따르고, 다른 점만 여기 적는다.

- 양식: `src/features/vendors/doc/FORMAT.md`, 예시 `src/features/vendors/doc/__fixtures__/samsung-tng.md`
- 축과 판정 규칙: `src/features/vendors/axes.ts` (6개 축, 축마다 책임 주체)

## 업체 카드 (목록화)

업체 카드는 게시된 사업 리포트에서 만든다. 평가 대상 기준(전략 v0.1, 사용자 확인 2026-10-29):

- **용역**만(학술·기술·일반·정보화). 공사·물품은 사업 리포트의 계약 상세에서 다룬다.
- 이 사업 안에서 같은 업체와 맺은 계약을 합쳐 **1억 원 이상**, 또는 사업비의 10% 이상.
- 계약이 끝났거나 1년 넘게 이어진 것을 우선순위 높게. 막 시작한 계약은 `low`.
- 공동수급체는 대표사로 카드를 만들고 `share`에 지분을 적는다.

순서: `vendors/{사업자등록번호}` 레지스트리 먼저(나라장터 조달업체 기본정보에서 법인명·소재지·개업일·종업원 수·등록 업무만) → `programs/{사업}/vendors/{번호}` 카드(`VendorCardSchema`). 목록화를 마치면 사업 카드에 `vendorsListedAt`을 적는다(평가할 업체가 없어도).

사업자등록번호는 시 계약정보공개에 없다. 나라장터 계약정보의 `corpList` 마지막 칸이나 개찰결과의 `prcbdrBizno`에서 얻는다. 개인사업자는 상호에 사람 이름이 있으면 ○○○로 가리고, 화면에는 사업자등록번호를 싣지 않는다(법인은 싣는다).

## 자료 모으기

사업 쪽 자료(`materials`에서 `subjects`에 사업 경로가 든 것)를 먼저 본다. 이 업체의 계약이 든 자료는 `subjects`에 업체 경로를 더하고 다시 받지 않는다.

### 나라장터 OpenAPI (`npm run catalog -- g2b`)

인증키는 `loop.env.local`의 `DATA_GO_KR_SERVICE_KEY`(이미 인코딩된 키, 도구가 그대로 쓴다). 도구가 대표자·담당 공무원 이름과 연락처를 지우고 저장한다. 저장한 JSON을 자료(`kind: 계약정보` 또는 `목록`, `publisher: 조달청`)로 올린다.

| 무엇                                                | 서비스 · 기능                                           | 인자                                                                |
| --------------------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------- |
| 계약 (사업자등록번호·공고번호·지체상금률·계약 방법) | `ao/CntrctInfoService getCntrctInfoListServcPPSSrch`    | `inqryDiv=1 inqryBgnDate=YYYYMMDD inqryEndDate=YYYYMMDD cntrctNm=…` |
| 개찰 순위·점수·부적격                               | `as/ScsbidInfoService getOpengResultListInfoOpengCompt` | `bidNtceNo=…`                                                       |
| 공고 (배정예산·추정가격·부가세·첨부 공고서 주소)    | `ad/BidPublicInfoService getBidPblancListInfoServc`     | `inqryDiv=2 bidNtceNo=…`                                            |
| 업체 기본정보                                       | `ao/UsrInfoService02 getPrcrmntCorpBasicInfo02`         | `inqryDiv=3 bizno=…`                                                |
| 부정당 제재                                         | `ao/UsrInfoService02 getUnptRsttCorpInfo02`             | `inqryDiv=1 bizno=…`                                                |

- 기간 검색은 한 달 안쪽으로 나눈다. 넓으면 `07 입력범위값 초과 에러`.
- 계약 검색 결과는 전국이다. `dminsttList`에 기관코드(`3940000`)가 든 줄만 쓴다.
- 2024년 이전 공고번호는 계약정보의 `ntceNo` 13자리 중 앞 11자리가 `bidNtceNo`다(`2022100523800` → `20221005238`). 2025년부터는 `R25BK…` 그대로.
- **사업금액 = 추정가격 + 부가세**(`presmptPrce + VAT`). 투찰률은 투찰 금액 ÷ 사업금액. 시 계약정보공개의 `schdAmt`(예정가격)와 같을 때도, 다를 때도 있다(2026년 고양시는 계약금액을 적었다). 나라장터 값을 쓰고 차이는 적는다.
- 부정당 제재 조회는 **조회 시점에 유효한 제재만** 준다(만료·해제는 안 나옴). 0건이면 “조회 시점 유효 제재 없음”까지만 쓴다.
- 공고서(hwp)는 공고의 `ntceSpecDocUrl1`을 `curl -sS -L`로 받고 `npm run catalog -- hwp-text original.hwp text.txt`. 사업금액·납품기한·참가자격·평가 비율(기술 90·가격 10)·투찰 하한 규칙이 여기 있다. 과업 범위를 담은 제안요청서는 보통 첨부에 없다(정보공개청구 대상).

### 시 계약정보공개 (고양시)

- 업체명 검색: `situationList.do`를 먼저 열어 세션 쿠키를 받고, `ajaxSituationList.do`에 JSON 본문 `{"custNm":"…","condCustNm":"…","pageIndex":1,"rowNum":100,"condRowNum":100}`. `rowNum`을 주지 않으면 한 건만 온다. 이 업체가 시와 맺은 계약 전체 → `## 다른 공공 계약` 맥락 표.
- 계약명 검색(`ctrtNm`)으로 같은 용역의 다른 해·공백 기간을 찾는다(예: 2026년 1~3월 계약 없음).
- 상세의 변경 이력(`situationAlterDataList`: 증감액과 사유), 지급(`optionalOfferDataList`: 선급금·기성금·준공금), 과업 정지(`situationProgchngDataList`)가 ③·⑤ 축의 근거다. 준공금까지 지급되고 잔액 0이면 검사를 거친 간접 기록이다(지방계약법 시행령 제64조·제67조). 검사조서 자체는 공개되지 않는다.
- 같은 사업의 원가계산 용역(‘원가계산’으로 검색)이 있으면 예정가격 산출 근거의 단서다.

### 의회 회의록

용역 이름과 **업체 이름**으로 둘 다 검색한다. 업체 이름은 선정 이의(가처분), 연속 수주 지적처럼 사업 리포트에서 안 보이던 대목을 찾아 준다.

## 사실 원장

- 업체 평가 대상 아래(`programs/{사업}/vendors/{번호}/facts/f{n}`)에 쓴다. 사업 쪽에 이미 있는 계약 사실은 다시 쓰지 않고, 계산된 사실의 `derivedFrom`에 경로(`programs/{사업}/facts/f6`)로 가리킨다.
- 귀책은 원문이 말한 만큼만. “업체 사유로 늦었다”는 원문이 그렇게 적었을 때만 쓴다.
- 함께 입찰한 다른 업체, 소송 상대 업체는 평가 대상이 아니므로 `claim`에 이름을 쓰지 않는다(“2순위 업체”). 원문 `quote`는 그대로 둔다.

## 리포트 초안

- 축 상태·근거 수준은 사실로 정한다. 종합 판정은 쓰지 않는다(규칙으로 계산). `## 종합 판정`에는 `### 다음 판단 시점`만 쓴다.
- 축 카드 제목(`####`)은 사이트 축 요약에 그대로 쓰이므로 제목만 읽어도 내용이 전해지게 쓴다.
- ① 선정의 문제는 업체 판정을 끌어내리지 않는다. 참고 블록에 “선정 방식은 조달청과 시가 정한다”를 적는다.
- `npm run pipeline -- put programs/{사업}/vendors/{번호}/reports/{기준일} report.md --status draft` → 통과하면 `--status in-review`.

## 검증할 때 더 볼 것 (verify-report와 함께)

검증 세션은 `verify-report`의 순서를 따르고 아래를 `high`로 본다.

- 귀책 주어: 원문에 업체 사유라는 말이 없는데 업체를 주어로 지연·부실을 쓴 문장.
- 개인정보: 대표자·직원 이름, 다른 업체 이름, 개인사업자 사업자등록번호가 본문에 있음.
- 확정 여부: 수사·소송 중인 사건을 처분처럼 쓴 문장.
- 책임 주체: 발주기관이 정한 것(선정 방식, 예정가격, 계약 기간)으로 업체 축을 ‘개선 필요’로 내린 곳.

## 끝낼 때

자료·사실·부재 기록 수, 리포트 기준일, 확인 못 한 것, 그리고 다음은 다른 세션의 검증이라고 알린다.

## 걸려 넘어진 것

(회차마다 실제로 고친 것·실패한 것을 여기 보탠다. 미리 짐작해 쓰지 않는다.)

2026-10-29 삼성티엔지(달릴고양) 예시:

- 공공데이터포털 키를 한 번 더 인코딩하면 403이 난다. 포털의 ‘인코딩’ 키는 그대로 붙인다(도구가 처리한다).
- `uvx pyhwp`는 루프 권한 검사에서 막혔다(외부 코드 내려받기). `npm run catalog -- hwp-text`를 쓴다.
- 2026년 고양시 계약정보는 예정가격 칸에 계약금액을 적어 낙찰률이 100으로 보였다. 나라장터 공고의 사업금액(13억 2,709만)으로 다시 계산하니 투찰률 80.0%였다.
- 시 계약정보공개는 2023~2025년 계약 방법을 ‘일반경쟁’으로, 나라장터는 ‘제한경쟁(중소기업자 간)’으로 적었다. 둘 다 적고 나라장터를 따랐다.
- 1·2순위가 같은 금액(사업금액의 정확히 80%)을 써냈다. 공고서의 “80% 미만이면 가격 점수 30%” 규칙 때문이다. 공고서를 읽지 않으면 이상 신호로 잘못 볼 수 있다.
- 투찰은 2025년 12월(12개월 과업 전제로 보임)인데 계약은 가처분 소송 뒤 4월 1일~12월 31일(9개월)에 같은 금액으로 맺어졌다. 의회 답변(“1분기가 감해진 금액”)과 기록이 맞지 않아 ⑤ 금액에 둘 다 적고 확인 필요로 남겼다.
- 에뮬레이터 테스트 문서가 지워지지 않아 `publishedVendors`를 읽는 화면이 깨진 적이 있다. 게시 문서가 가리키는 리포트가 없으면 목록 전체를 못 읽는다.
