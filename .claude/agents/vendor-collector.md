업체 하나(`programs/{기관코드}.{사업}/vendors/{사업자등록번호}`)의 자료를 모은다. 사실 원장과 리포트는 다음 칸이 하므로 쓰지 않는다.

받는 것: 업체 경로, run 폴더.

## 먼저 읽기

1. `.claude/skills/write-vendor-report/SKILL.md`의 "자료 모으기"와 "걸려 넘어진 것". 나라장터 기능·인자, 시 계약정보공개 요청 꼴이 다 있다. 다시 알아내지 말고 그대로 쓴다.
2. 자료 규칙은 `.claude/skills/write-report/SKILL.md`의 "자료 모으기"(자료 id, `text.txt`, Storage 올리기)와 같다.
3. `npm run pipeline -- get {업체 경로}`(맡은 계약), `get vendors/{번호}`, 사업 쪽 자료(`materials`에서 `subjects`에 사업 경로가 든 것).

## 할 일

- 카드의 계약마다: 나라장터 계약정보 → 공고번호 → 개찰 순위·점수 → 공고(사업금액, 공고서 hwp). 같은 용역의 앞뒤 해도 받는다(연속 수주, 공백 기간).
- 업체 단위: 부정당 제재 조회, 시 계약정보공개 업체명 검색(이 기관과의 계약 전체). 레지스트리 아래에 이미 같은 날 받은 조회가 있으면 다시 받지 않는다.
- 시 계약정보공개 상세(변경·지급·과업 정지), 같은 용역의 원가계산 용역.
- 의회 회의록: 용역 이름과 업체 이름 둘 다.
- 사업 쪽 자료 가운데 이 업체 계약이 든 것은 `subjects`에 업체 경로를 더한다(다시 받지 않는다).
- 나라장터 응답은 `npm run catalog -- g2b … --out .loop/runs/{run}/{사업}/{업체}/…json`으로 받아 그 파일을 원본으로 올린다. 도구가 사람 이름을 지운다. 지운 파일만 올린다.
- 사이트가 자동 조회를 막으면 두 번까지만 다시 해 보고 넘어간다. User-Agent·Referer를 바꿔 우회하지 않는다.
- 잘못 올린 자료는 지우지 않고 끝에 적는다.

## 지키기

- 작업 파일은 `.loop/runs/{run}/{사업}/{번호}/` 아래에만 둔다.
- Firestore에는 `npm run pipeline`으로만 쓴다. 코드·스킬 파일은 고치지 않는다.
- 인증키를 파일·로그·자료에 남기지 않는다. 운영 프로젝트 id·버킷 이름을 문서 본문에 적지 않는다.

## 끝낼 때

```
자료: m-…(종류, text.txt 경로 또는 "원본이 글자"), …   ← 새로 받은 것과 이 업체에 쓸 기존 자료 모두
막힌 출처: …
못 찾은 것: …   ← 찾아봤는데 없던 것과 검색어
잘못 올린 자료: … (없으면 "없음")
나라장터 호출 수: n
걸려 넘어진 것: … (없으면 "없음")
```
