사업 하나(`programs/{기관코드}.{사업}`)의 자료를 모은다. 사실 원장과 리포트는 다음 칸이 하므로 쓰지 않는다.

## 먼저 읽기

1. `.claude/skills/write-report/SKILL.md`의 "자료 모으기"와 "걸려 넘어진 것". 출처별로 이미 알아낸 요령(지방재정365 상세, 회의록 검색, 계약정보, hwp·hwpx 글자 뽑기, Storage 올리기)이 있다. 다시 알아내지 말고 그대로 쓴다.
2. `npm run pipeline -- get programs/{id}`로 카드를 보고, `materials`에서 `subjects`에 이 경로가 든 자료와 상위 사업·같은 부서의 자료를 확인한다. 이미 받은 자료는 다시 받지 않는다.

## 할 일

- 출처는 공식 공개 자료와 지역 언론: 지방재정365 세부사업 상세(연도별), 기관 누리집 보도자료·고시공고·예산서, 지방의회 회의록(검색어 띄어쓰기 변형까지), 계약정보, 감사 결과, 법령, 지역 언론 기사.
- 자료 한 건 = `materials/m-{원본 sha256 앞 12자리}`. 원본은 `.storage/materials/{id}/original.{확장자}`. 글자가 아닌 원본(PDF·hwp·hwpx·엔티티가 든 HTML)은 같은 폴더에 `text.txt`를 만든다. 다음 칸(발췌)은 `text.txt`가 있어야 읽는다.
- Storage 같은 경로로 올린다(`GLASSES_STORAGE_BUCKET`).
- 사이트가 자동 조회를 막으면 두 번까지만 다시 해 보고 넘어간다. 막힌 출처는 끝에 적는다. User-Agent·Referer를 바꿔 막힘을 우회하지 않는다.
- 회의록 검색은 사업 이름의 띄어쓰기 변형과 줄임(‘정발산공원 전망대’, ‘정발산 전망대’, ‘정발산 구상’)을 모두 돌린다. 변형마다 결과가 달라 결산 회의록을 놓친 적이 있다. 의안 첨부(동의안, 결산검사 의견서)도 찾는다.
- 출자·출연기관 사업이면 그 기관의 경영공시(감사 결과, 결산서, 경영실적 평가)를 찾는다.
- 회의록은 뷰어 `<title>`과 본문 표지가 다를 수 있다. 등록 전에 표지와 대조한다.
- `curl`은 `-sS`로 쓴다(`-s`만 쓰면 실패가 숨는다).
- **잘못 올린 자료는 지우지 않는다.** Firestore·Storage를 REST나 gcloud로 직접 고치거나 지우지 않는다. 끝낼 때 "잘못 올린 자료"로 적으면 사람이 정리한다.

## 지키기

- 작업 파일(스크립트, JSON, 내려받은 파일)은 `.loop/runs/{run}/{사업}/` 아래에만 둔다. 스크래치패드나 `/tmp`에 쓰지 않는다. 같은 실행의 다른 일꾼과 그 폴더를 같이 써서 같은 이름의 파일이 서로 덮인다.
- Firestore에는 `npm run pipeline`으로만 쓴다. 코드, 스킬 파일, 다른 사업의 문서는 고치지 않는다(기관 공통 자료나 다른 사업에 붙은 자료가 이 사업에도 닿으면 그 자료의 `subjects`에 이 사업을 더하는 것만 된다).
- 운영 프로젝트 id·버킷 이름을 파일이나 문서 본문에 적지 않는다.

## 끝낼 때 (오케스트레이터에게 돌려줄 것)

```
자료: m-…(종류, text.txt 경로 또는 "원본이 글자"), …   ← 이번에 새로 받은 것과 이 사업에 쓸 기존 자료 모두
막힌 출처: …
못 찾은 것: …
잘못 올린 자료: … (없으면 "없음")   ← 찾아봤는데 없던 것과 검색어
걸려 넘어진 것: …   ← 다음에 시간을 아낄 요령. 없으면 "없음"
```
