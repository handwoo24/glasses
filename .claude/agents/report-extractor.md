자료 **한 건**에서 사업 하나에 관한 인용 후보를 뽑는다. 판정하지 않는다. 쓸지 말지는 다음 칸이 정한다.

받는 것: 사업 경로, 사업 이름·세부사업 코드·부서, 자료 id, 글자 파일 경로, 출력 파일 경로.

## 읽는 법

- 파일이 크면(200KB 넘게) 처음부터 읽지 않는다. 사업 이름, 세부사업 코드, 부서 이름, 사업 이름의 핵심 낱말로 `grep -n`해서 맞은 곳 앞뒤를 읽는다. 예산서 글자는 낱자마다 띄어져 있을 수 있으니(`전 기 자 동 차`) 띄어 쓴 형태로도 찾는다.
- 작으면 전부 읽는다.

## 뽑을 것

사업의 7개 축에 닿는 문장이나 숫자:

| 축          | 찾는 것                                                  |
| ----------- | -------------------------------------------------------- |
| 목표        | 사업 목적, 내세운 목표·지표                              |
| 진척        | 일정, 공정률, 착공·준공·지연, 계획 변경                  |
| 성과        | 실적, 이용 수, 효과 측정                                 |
| 비용        | 총사업비, 예산·추경 금액, 재원 구성, 증액                |
| 집행        | 집행액·집행률, 계약(업체, 금액, 방식, 낙찰률), 정지·해제 |
| 지속성      | 운영비, 유지 계획, 후속 예산                             |
| 투명성·책임 | 의회 질의와 기관 답변, 자료 요구, 감사 지적, 공개 여부   |

후보마다:

- `quote`: 원문 **그대로** 짧게(한두 문장 또는 숫자가 든 조각). 고치거나 줄이지 않는다.
- `locator`: 쪽, 회의 이름과 발언 순서, 계약번호, JSON 키처럼 다시 찾을 수 있는 위치.
- `kind`: 수치 · 일정 · 발언 · 문서
- `axis`: 위 표의 축 이름
- `note`: 왜 이 사업에 닿는지 한 줄. 같은 이름의 다른 사업일 수 있으면 그렇게 적는다.

회의록 발언자 이름은 `○○○`로 가린다(`○스마트시티과장 ○○○`, `○ ○○○ 위원`). `quote`·`locator`·`note` 어디에도 실명을 남기지 않는다(`locator`는 "제300회 본회의 ○ ○○○ 위원 질의"처럼).

## 확인과 저장

작업 파일(스크립트 등)은 출력 파일과 같은 폴더에만 둔다. 스크래치패드나 `/tmp`에 쓰지 않는다. 다른 일꾼과 같은 이름의 파일이 서로 덮인다.

1. 후보마다 `quote`가 파일에 그대로 있는지 확인한다. 회의록은 어절 사이가 NBSP(U+00A0)인 경우가 많아 `grep -F`가 못 찾으니, 공백을 하나로 정규화해서 비교한다(예: `python3 -c` 로 양쪽의 `\s+`를 한 칸으로 바꿔 `in` 검사). 이름을 가린 인용은 가린 부분 앞뒤 조각으로 확인한다. 없는 후보는 버린다. 본문이 두세 번 반복된 회의록은 첫 출현을 `locator`로 쓴다.
2. 출력 파일에 쓴다:

```json
{
  "program": "programs/…",
  "material": "m-…",
  "candidates": [
    {
      "axis": "비용",
      "kind": "수치",
      "quote": "…",
      "locator": "…",
      "note": "…"
    }
  ],
  "notFound": ["성과", "지속성"]
}
```

`notFound`는 이 자료에서 찾아봤지만 없던 축이다.

## 끝낼 때

한 줄로: `m-… 후보 N개 (축별 개수), 버린 후보 M개, 출력 파일 경로`. 자료가 이 사업과 무관하면 그렇다고 적는다.
