# 리포트 문서 양식

리포트 한 건은 마크다운 문서 하나(`<slug>.md`)다. 사람이 그대로 읽을 수 있게 쓰고, 웹은 이 문서를 읽어 디자인 시스템에 맞춰 그린다. 읽는 코드는 [`src/features/reports/doc/load.ts`](../../features/reports/doc/load.ts)이고, 양식이 틀리면 어느 구역이 왜 틀렸는지 알려 주며 실패한다. 실패한 문서는 게시되지 않는다.

예시: [autonomous-bus-dallil-goyang.md](autonomous-bus-dallil-goyang.md)

## 공통 규칙

- **출처**: 문장 끝에 `[s3][s1]`처럼 붙인다. id는 맨 아래 `## 출처` 표에 있어야 하고 표 안에서 겹치면 안 된다. 출처를 붙이는 자리는 정해져 있다: 리드, 사실·시의 설명 목록, 라벨 뒤 내용(아직 확인하지 못한 것 항목·점검 질문·지표·감사·공개 문서·예산 단계), 표의 설명 칸, 패널·그림 본문. 판정 문단, 한 줄 요약, 축 제목, **시민 단위**, **확인 못 한 것**, 점검의 발견·판단 기준 같은 칸에 붙이면 화면에 글자로 보이므로 오류다. 한 문장으로 된 칸은 출처를 문장 끝에만 붙인다. 코드 블록(청구 문구) 안의 `[s1]`은 출처로 보지 않는다.
- **라벨**: 목록 항목이나 문단 첫머리의 `**라벨**`은 값을 뜻한다. 라벨을 지시자로 쓰는 변형은 정한 자리에서만 쓴다: `:req[…]`는 확인 못 한 것·패널 목록, `:night[…]`는 `:::routes`. 화면에 쓰는 한국어 라벨을 그대로 쓴다(예: `**확인 필요**`, `**해당 · 중요도 높음**`). 라벨 목록은 [`labels.ts`](../../features/reports/labels.ts), [`axes.ts`](../../features/reports/axes.ts), [`assessment.ts`](../../features/reports/assessment.ts)의 `ANSWER_INFO`에 있다.
- **쓸 수 없는 것**: HTML, 번호 목록, 기울임, 인라인 코드, 이미지, 빈 목록 항목, 정해지지 않은 블록·지시자·속성(속성은 `next-date`의 `date`, `split`의 `label`만). 제목(`##`~`####`)은 글자만 쓴다. 링크는 출처 도메인이나 시민 안내 도메인(`schema.ts`)의 https 주소만 쓴다.
- **범위 표기**: `2023~2026년`처럼 `~` 하나는 범위로 읽는다(취소선 아님).
- **줄 머리 숫자**: 문단이나 항목이 `2026. 10.`처럼 "숫자 + 마침표"로 시작하면 번호 목록이 되므로 `2026\. 10.`으로 쓴다. 표 칸과 라벨 안에서는 그대로 써도 된다.
- **Prettier 제외**: 이 폴더의 리포트 문서는 Prettier가 지시자(`:::`)를 깨뜨려서 `.prettierignore`에 넣었다.

```yaml

description: … # 검색·공유용 한두 문장
asOf: 2026-10-27 # 자료 기준일
nextReview: 2026-12 # 다음 갱신 예정
facts: # 제목 아래 사실 줄 (순서대로)
  주관: 고양특례시 스마트시티과
  총사업비: 402억 원
typeNote: 이 사업은 … 유형입니다. # 선택

  goal: …
footNote: 1명당 금액은 … # 출처 목록 아래 각주

```

## 본문 순서

`#` 제목, 리드 문단(문장 끝 출처) 다음에 `##` 구역이 온다. 문서마다 제목이 다른 패널은 제목 끝에 `{#side}` `{#status}` `{#vendors}`를 붙인다.

| 구역                       | 필수 | 내용                                                                                                                          |
| -------------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------- |
| `## 사업 개요`             | ○    | 표 `구분 \| 요약 \| 설명`(구분은 무엇·얼마·누가·언제 순서로 한 번씩). 선택: `### 묶음 이름 [s3]` + 목록(이 사업은 `**굵게**`) |
| `## (제목) {#side}`        | ○    | 자유 본문(패널)                                                                                                               |
| `## 종합 판정`             | ○    | 판정 문단 하나 + `### 다음 판단 시점` 목록 `- **11. 10.** 첫 실적 보고`                                                       |
| `## (제목) {#status}`      | ○    | 자유 본문(패널)                                                                                                               |
| `## 축별 근거`             | ○    | 7개 축, 아래 "축" 참고                                                                                                        |
| `## (제목) {#vendors}`     |      | 자유 본문(패널)                                                                                                               |
| `## 아직 확인하지 못한 것` | ○    | `- **라벨** 내용 [s6]`. 요청했는데 못 받은 것은 `- :req[라벨] 내용`                                                           |
| `## 더 알아보는 방법`      | ○    | `### 정보공개청구 문구` + 코드 블록, 선택: `### 그 밖의 방법` + 목록                                                          |
| `## 점검표`                | ○    | 아래 "점검표" 참고                                                                                                            |
| `## 예산이 정해진 과정`    |      | 소개 문단 + `- **단계** 설명 [s1]`                                                                                            |
| `## 계약 상세`             |      | 소개 문단 + 계약마다 `### 계약명 [s10]` + ` ```yaml ` (schema.ts의 `ContractSchema`에서 name·cite를 뺀 것)                    |
| `## 감사·점검 이력`        |      | `- **기록 없음 · 2022~2026년** 기관 [s26]` / 결과 문단 / `**그 뒤** …`                                                        |
| `## 공개 문서 현황`        |      | `- **공개 자료에서 찾지 못함 · 게시 의무 · 청구 전** 문서 [s1]` / 설명 문단                                                   |
| `## 진행 경과`             | ○    | 표 `날짜 \| 내용`(날짜는 `2026-10` 또는 `2026-10-20`)                                                                         |
| `## 출처`                  | ○    | 표 `id \| 자료 \| 기관 \| 종류 \| 날짜 \| 위치 \| 이용조건`, 자료 칸은 `[제목](주소)`                                         |

### 축

```markdown
### ④ 비용 · 개선 필요 · 근거 일부

> 종합 판정 목록에 들어갈 한 줄 (한다체).

#### 축 카드 제목 (합니다체)

- 사실 한 문장. [s3][s1]

::::figure
(그림: 아래 "그림" 참고)
::::

**시민 단위** 시민 1명당 …

**시의 설명**

- 직함(2024. 12.): 요약. [s6]

**참고** 덧붙일 말. [s18]

**확인 못 한 것** 아직 보지 못한 자료
```

- 축 제목은 `번호 이름 · 상태 · 근거 수준` 세 부분이다. 상태는 순항·지켜볼 점·개선 필요·판단 불가, 근거 수준은 근거 충분·근거 일부·근거 부족이다.
- 7개 축이 ①~⑦ 순서로 하나씩 있어야 한다. 한 줄 요약(`>`)과 `####` 제목은 필수이고 나머지는 선택이다. 각 블록은 한 축에 한 번만 쓴다(두 번 쓰면 오류).
- `**시의 설명**`은 라벨만 쓴 문단이고 바로 다음에 목록이 와야 한다. 축 안에 위에 적은 것 말고 다른 블록이 오면 오류다.
- 종합 판정은 쓰지 않는다. 축 상태로 [`axes.ts`](../../features/reports/axes.ts)의 규칙에 따라 계산한다.

### 점검표

```markdown
### ④ 비용

- **확인 필요** 운영 용역 입찰에 여러 업체가 참여했는가 [s14][s13]

  발견한 것 (한 문단)

  **판단 기준** 무엇에 비춰 답을 정했나

#### 관련 지표

- **해당 · 중요도 높음** 지표 이름 [s10]

  설명 (한 문단)
```

답 라벨은 충족·미충족·확인 필요·자료 없음이다. 점검이 없는 축의 `###`은 빼도 된다.

## 패널 본문 (side, status, vendors)

| 쓰는 법                                                                                                       | 화면           |
| ------------------------------------------------------------------------------------------------------------- | -------------- |
| 문단                                                                                                          | 문단           |
| `- **라벨** 내용`                                                                                             | 라벨 붙은 목록 |
| `:::routes` 목록 `- **주간 1** …`, 강조 노선은 `- :night[야간] …`                                             | 노선 목록      |
| `:::kv` 목록 `- **요금** 무료`                                                                                | 항목-값 목록   |
| `:::next-date[다음 날짜]{date=2026-11-10}` + 문단                                                             | 큰 날짜        |
| `:::table[표 설명]` + 표. 첫 칸은 행 제목, 오른쪽 정렬(`---:`) 칸은 숫자 칸, 칸 안의 `:grp[묶음]`은 묶음 표시 | 표             |

## 그림 (`::::figure` 안)

| 쓰는 법                                                                               | 화면                  |
| ------------------------------------------------------------------------------------- | --------------------- |
| `#### 소제목`                                                                         | 그림 소제목           |
| 목록                                                                                  | 출처 붙은 사실 목록   |
| 문단 / `**시민 단위** …`                                                              | 그림 설명 / 시민 단위 |
| `:::split{label="화면 낭독용 요약"}` + 항목 두 개                                     | 둘로 나눈 막대        |
| ` ```bars ` YAML(`label`, `bars: [{year, text, height, hot?}]`)                       | 세로 막대             |
| `:::flow` 목록 `- **이름** 설명 [s3]`, 하위 목록이 있는 항목은 묶음(이름 = 묶음 설명) | 돈의 흐름             |
| `:::state` 목록, 항목 끝에 `:ok[없음]` `:warn[…]` `:bad[…]` `:none[…]`                | 상태 목록             |

`::::figure`처럼 바깥 블록은 콜론을 하나 더 쓴다.
