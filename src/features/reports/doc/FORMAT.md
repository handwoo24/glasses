# 리포트 문서 양식

리포트 한 건은 마크다운 문서 하나(`<slug>.md`)다. 사람이 그대로 읽을 수 있게 쓰고, 웹은 이 문서를 읽어 디자인 시스템에 맞춰 그린다. 읽는 코드는 [`src/features/reports/doc/load.ts`](load.ts)이고, 양식이 틀리면 어느 구역이 왜 틀렸는지 알려 주며 실패한다. 실패한 문서는 게시되지 않는다.

예시: [**fixtures**/autonomous-bus.md](__fixtures__/autonomous-bus.md) (테스트 자료. 게시 리포트의 원본은 Firestore에 있다)

## 공통 규칙

- **출처**: 문장 끝에 `[s3][s1]`처럼 붙인다. id는 맨 아래 `## 출처` 표에 있어야 하고 표 안에서 겹치면 안 된다. 출처를 붙이는 자리는 정해져 있다: 리드, 사실·기관의 설명 목록, 라벨 뒤 내용(아직 확인하지 못한 것 항목·점검 질문·지표·감사·공개 문서·예산 단계), 표의 설명 칸, 패널·그림 본문. 한 줄 요약, 축 제목, **시민 단위**, **확인 못 한 것**, 점검의 발견·판단 기준 같은 칸에 붙이면 화면에 글자로 보이므로 오류다. 한 문장으로 된 칸은 출처를 문장 끝에만 붙인다. 코드 블록(청구 문구) 안의 `[s1]`은 출처로 보지 않는다.
- **라벨**: 목록 항목이나 문단 첫머리의 `**라벨**`은 값을 뜻한다. 라벨을 지시자로 쓰는 변형은 정한 자리에서만 쓴다: `:req[…]`는 확인 못 한 것·패널 목록, `:night[…]`는 `:::routes`. 화면에 쓰는 한국어 라벨을 그대로 쓴다(예: `**확인 필요**`, `**해당 · 중요도 높음**`). 라벨 목록은 [`labels.ts`](../labels.ts), [`axes.ts`](../axes.ts), [`assessment.ts`](../assessment.ts)의 `ANSWER_INFO`에 있다.
- **쓸 수 없는 것**: HTML, 번호 목록, 기울임, 인라인 코드, 이미지, 빈 목록 항목, 정해지지 않은 블록·지시자·속성(속성은 `next-date`의 `date`, `split`의 `label`만). 제목(`##`~`####`)은 글자만 쓴다. 링크는 출처 도메인이나 시민 안내 도메인(`schema.ts`)의 https 주소만 쓴다.
- **범위 표기**: `2023~2026년`처럼 `~` 하나는 범위로 읽는다(취소선 아님).
- **줄 머리 숫자**: 문단이나 항목이 `2026. 10.`처럼 "숫자 + 마침표"로 시작하면 번호 목록이 되므로 `2026\. 10.`으로 쓴다. 표 칸과 라벨 안에서는 그대로 써도 된다.
- **Prettier 제외**: Prettier가 지시자(`:::`)를 깨뜨리므로 리포트 문서를 Prettier로 고치지 않는다(테스트 자료는 `.prettierignore`에 넣었다).

## 본문 순서

`#` 제목, 리드 문단(문장 끝 출처) 다음에 `##` 구역이 온다. 문서마다 제목이 다른 패널은 제목 끝에 `{#side}` `{#status}` `{#vendors}`를 붙인다.

| 구역                       | 필수 | 내용                                                                                                                          |
| -------------------------- | ---- | ----------------------------------------------------------------------------------------------------------------------------- |
| `## 사업 개요`             | ○    | 표 `구분 \| 요약 \| 설명`(구분은 무엇·얼마·누가·언제 순서로 한 번씩). 선택: `### 묶음 이름 [s3]` + 목록(이 사업은 `**굵게**`) |
| `## (제목) {#side}`        | ○    | 자유 본문(패널)                                                                                                               |
| `## 종합 판정`             | ○    | `### 다음 판단 시점` 목록만 `- **11. 10.** 첫 실적 보고`. 판정 문단은 쓰지 않는다(아래)                                       |
| `## (제목) {#status}`      | ○    | 자유 본문(패널)                                                                                                               |
| `## 축별 근거`             | ○    | 7개 축, 아래 "축" 참고                                                                                                        |
| `## (제목) {#vendors}`     |      | 자유 본문(패널)                                                                                                               |
| `## 아직 확인하지 못한 것` | ○    | `- **라벨** 내용 [s6]`. 요청했는데 못 받은 것은 `- :req[라벨] 내용`                                                           |
| `## 더 알아보는 방법`      | ○    | `### 정보공개청구 문구` + 코드 블록, 선택: `### 그 밖의 방법` + 목록                                                          |
| `## 점검표`                | ○    | 아래 "점검표" 참고                                                                                                            |
| `## 예산이 정해진 과정`    |      | 소개 문단 + `- **단계** 설명 [s1]`                                                                                            |
| `## 계약 상세`             |      | 소개 문단 + 계약마다 `### 계약명 [s10]` + ` ```yaml ` (schema.ts의 `ContractSchema`에서 name·cite를 뺀 것)                    |
| `## 감사·점검 이력`        |      | `- **기록 없음 · 2022~2026년** 기관 [s26]` / 결과 문단 / `**그 뒤** …`                                                        |
| `## 공개 문서 현황`        |      | `- **공개 자료에서 찾지 못함 · 게시 의무 · 청구 전** 문서 [s1]` / 설명 문단                                                   |
| `## 진행 경과`             | ○    | 표 `날짜 \| 내용`(날짜는 `2026-10` 또는 `2026-10-20`)                                                                         |
| `## 출처`                  | ○    | 표 `id \| 자료 \| 기관 \| 종류 \| 날짜 \| 위치 \| 이용조건`, 자료 칸은 `[제목](주소)`. 종류는 아래 "출처 종류"                |

### 다음 판단 시점

`### 다음 판단 시점` 목록의 라벨은 사람이 읽는 날짜를 그대로 쓴다: `11. 10.`, `11. 12.~19.`, `12월`, `2027년 상반기`, `2027. 2. 3.`. 연도를 빼면 기준일(`asOf`) 뒤로 처음 오는 해로 본다(기준일이 10월이면 `1. 15.`는 다음 해). 화면은 이 날짜로 D-day를 세고 홈에서 날짜순으로 모은다. 범위는 시작 날짜로 정렬하고, 읽을 수 없는 라벨(‘추후 공지’)은 맨 뒤에 둔다.

### 출처 종류

`보도자료` `예산서` `회의록` `계약정보` `공고` `집행정보` `감사` `법령` `목록` `기타` 가운데 하나. 파이프라인 자료 종류(`MATERIAL_KINDS`)와 같다. 지방재정365·열린재정 같은 집행 통계는 `집행정보`, 감사 결과는 `감사`, 법령·예규는 `법령`, 게시판·목록 화면은 `목록`. 화면의 출처 칩은 이 이름과 번호로 보인다(‘회의록 6’). `기타`는 칩이 ‘자료’로 보이므로 되도록 쓰지 않는다.

### 축

```markdown
### ④ 비용 · 개선 필요 · 근거 일부

> 종합 판정 목록에 들어갈 한 줄 (한다체).

#### 축 카드 제목 (합니다체)

- **문서** 사실 한 문장. [s3][s1]

::::figure
(그림: 아래 "그림" 참고)
::::

**시민 단위** 시민 1명당 …

**기관의 설명**

- 직함(2024. 12.): 요약. [s6]

**참고** 덧붙일 말. [s18]

**확인 못 한 것** 아직 보지 못한 자료
```

- 축 제목은 `번호 이름 · 상태 · 근거 수준` 세 부분이다. 상태는 순항·지켜볼 점·개선 필요·판단 불가, 근거 수준은 근거 충분·근거 일부·근거 부족이다.
- 7개 축이 ①~⑦ 순서로 하나씩 있어야 한다. 한 줄 요약(`>`)과 `####` 제목은 필수이고 나머지는 선택이다. 각 블록은 한 축에 한 번만 쓴다(두 번 쓰면 오류).
- 사실 목록 항목 첫머리에 근거 종류를 붙일 수 있다: `**발언**`(회의·인터뷰에서 한 말), `**문서**`(공식 문서·통계에 적힌 것), `**계산**`(glasses가 원문 숫자로 계산한 것). 사실 원장의 `kind`가 발언이면 발언, 계산된 사실이면 계산, 그 밖에는 문서다. 화면에서 문장 앞에 작은 표시로 보인다. 붙이지 않아도 되지만, 붙인다면 이 셋만 쓴다(다른 라벨은 오류).
- `**기관의 설명**`은 라벨만 쓴 문단이고 바로 다음에 목록이 와야 한다. 옛 문서의 `**시의 설명**`도 같은 뜻으로 읽는다. 축 안에 위에 적은 것 말고 다른 블록이 오면 오류다.
- 종합 판정은 쓰지 않는다. 축 상태로 [`axes.ts`](../axes.ts)의 규칙에 따라 계산한다. `## 종합 판정` 구역에도 판정 문단을 쓰지 않는다. 화면은 판정 띠(판정·근거 수준)와 다음 판단 시간선만 보이고, 판정의 내용은 핵심 내용(축 카드 제목)과 판정 이유가 맡는다. 판정 문단이 있는 옛 판은 읽히지만 새로 쓰면 문장 규칙에 걸린다.

### 점검표

```markdown
### ④ 비용

- **확인 필요** 운영 용역 입찰에 여러 업체가 참여했는가 [s14][s13]

  발견한 것 (한 문단)

  **판단 기준** 무엇에 비춰 답을 정했나

```

답 라벨은 충족·미충족·확인 필요·자료 없음이다. 점검이 없는 축의 `###`은 빼도 된다.

## 막대 블록

YAML로 쓴다. 쉼표가 들어간 글자(`"397억 5,500만"`)는 따옴표로 감싼다. 막대 설명과 출처는 블록 바로 다음 문단에 쓴다.

````yaml
# ```hbars — 가로 막대. 강조할 막대 하나만 hot
label: '화면 낭독용 요약' # 선택
max: 100 # 선택. 막대 100%에 해당하는 값 (비율이면 100)
rows:
  - { name: 기금 융자, value: 397.55, text: '397억 5,500만', hot: true }
  - { name: 세외수입, value: 392.12, text: '392억 1,223만' }
````

````yaml
# ```bars — 세로 막대(연도별). height는 막대 높이(px)
label: '화면 낭독용 요약'
bars:
  - { year: '2025', text: '7,230만', height: 72 }
  - { year: '2026', text: '1억 1,796만', height: 118, hot: true }
````

## 저장과 전달

리포트 문서는 코드가 아니라 Firestore에 둔다. 평가 대상(`programs/{기관코드}.{사업}` 또는 `orgs/{기관코드}/budgets/{연도-구분}`) 아래 `reports/{기준일}`에 `markdown`으로 들어가고, 파이프라인 도구(`npm run pipeline -- put … report.md`)가 이 양식과 문장 규칙([`lint.ts`](lint.ts))을 검사한 뒤에만 쓴다.

사이트에 보이는 리포트는 `published/{주소}` 문서가 정한다. 서버([`../server/report-docs.server.ts`](../server/report-docs.server.ts))가 게시 리포트를 읽어 파싱하고, 브라우저는 서버 함수로 검사를 마친 결과 JSON만 받는다. 본문 조각은 마크다운 트리(mdast) 그대로 받아 [`rich.tsx`](rich.tsx)로 그린다. 막대 블록은 서버에서 JSON으로 바뀌어 간다.
